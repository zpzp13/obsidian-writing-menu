# Document transfer architecture

## Data flow

`Vault snapshot → TransferDocument → content policy + DocumentStyle → codec → generated bytes → preview + save`

`WritingDocument` remains the editor integration abstraction. `src/export/DocumentModel.ts` defines a separate, versioned transfer model: paragraphs/headings, inline text and explicit LF, empty paragraphs, marks, notes, tables, images/resources, source ranges and optional native package parts. No editor, filesystem or renderer object is stored in it. `DocumentCodec` exposes `encode` and an optional future `decode` contract. This release does not implement import or show an import action.

A future importer can decode DOCX/HWPX to the same model, retain unsupported native XML in `native.parts`, and map source ranges/marks to Markdown and plugin formatting. The current Markdown adapter is export-focused; exact Markdown/native roundtrip is not promised. Lists/quotes retain literal source lines. Table spans, drawings, formulas and native document layout restoration need future model/adapter extensions.

## Snapshot and text preservation

`ExportService` flushes the selected open Markdown and Paged views, then reads manuscript text through `vault.read`. Paged inline marks/colors are applied to source ranges. `MarkdownDocument` uses markdown-it with typographic replacement disabled, parses original paragraph source, and restores source lines the Markdown parser omits. Its newline rule retains surrounding whitespace/tabs. A document newline is distinct from a paragraph boundary. A trailing LF has an empty final paragraph. Metadata removal consumes the frontmatter delimiter line ending, not manuscript blank lines.

Frontmatter is retained as a paragraph with the `properties` role and an original source range. The content policy can include its raw YAML body as plain text or exclude it, independently of manuscript whitespace. Merging retains each source's property block in place. Existing defaults/presets normalize headings/tables/footnotes to text/exclude, images to embed/exclude and the removed one-space indentation option to false. The separate `formatting` flag defaults to false. Tables remain tab-separated text. With formatting enabled, included headings retain their level and included footnotes become native notes; otherwise both are plain text.

`ProjectExportStyles` resolves the project's actual heading/footnote CSS rules in an invisible, temporary styled document root. It captures Style Settings typography and theme fallbacks as serializable pt/font/weight/color/line-spacing values in `EncodeOptions.elementStyles`. DOCX and HWPX use that same snapshot for their generated headings and native footnotes. No DOM object crosses the Worker boundary, no permanent probe is retained, and TXT ignores these styles.

`ExportFontWeights` resolves non-binary weights through the existing local-font API cache. It matches upright installed faces and weight-labelled family aliases, follows CSS's nearest-weight ordering, and serializes the named face in `EncodeOptions.fontFaces`. DOCX/HWPX use named faces for intermediate weights, while regular/bold keep their native flags; named heavy faces do not receive a second synthetic bold flag. Source defaults/presets retain the original 100–900 value. An unavailable exact face uses the nearest installed face, or native regular/bold if local metadata is unavailable; the popup reports that substitution in its status line. No font file is read from the filesystem or embedded. Variable fonts without independently named weight faces cannot carry arbitrary axis values through these native font-name/bold properties.

Content policy is applied after merging so notes receive consistent numbering. Source image identifiers are resolved through metadataCache/Vault, and `vault.readBinary` supplies only selected visible resources. Percent signs in literal wiki filenames do not require valid URI encoding. PNG/JPEG data is preserved; GIF/BMP/WebP/SVG is decoded locally into a portable PNG through browser canvas. Non-image wiki embeds are not treated as picture files. Images fit both body width and height, and decode errors name the source file. Remote schemes are rejected in embed mode. Image selection does not trigger any network request.

Image headers determine the embedded media type, independently of the source filename extension. A JPEG saved with a `.png` filename is embedded as JPEG without changing the source. The JPEG size reader handles metadata segments, fill bytes and standalone markers with segment bounds checks. When a supported raster header cannot supply dimensions, browser decoding provides the PNG conversion fallback.

## Codecs and preview

- TXT: `TextEncoder`, UTF-8 without BOM; preview shows exactly the final text.
- DOCX: pinned docx 9.14.0 serializes the model directly. docx-preview 0.4.1 renders the resulting bytes inside a ShadowRoot, with altChunk rendering disabled. The wrapper prevents exported styles from affecting the plugin. Word pagination can differ.
- HWPX: `StyledHwpxDocument` extends the verified blank HWPX/fflate packaging. It writes native paragraphs, lineBreak/tab controls, marks, notes, basic tables and raster resources. `mimetype` is first and uncompressed. Stale line segment caches and preview images are omitted.
- kordoc 4.24.6 supplies only SVG/reflow and its style/XML dependency graph. The pinned revision, source hashes and browser adaptations are in `vendor/kordoc/provenance.json`; full license is in `vendor/kordoc/LICENSE`. The CLI, template role classifier, OCR, PDF and native modules are excluded. No automatic cleanup/generator pipeline is called.

The Worker is embedded into main.js for the normal three-file community installer. Generation, archive processing and HWPX reflow run in this Worker; DOM preview rendering stays in the UI. The popup debounces changes for 250ms, coalesces identical pending states and discards obsolete generation IDs. A new preview aborts the previous snapshot pipeline and terminates an outstanding generation Worker, so a stale merged layout cannot queue newer work behind it. Snapshot reads check the abort signal before submitting another job. Worker errors, unreadable replies and a 120-second generation timeout reject the request instead of leaving the progress status pending. Closing terminates the Worker and rejects pending requests; object URLs are revoked. Save locks options, flushes live content again and reuses the cached generated result when unchanged. The renderer and filesystem writer use the same byte array; there is no second exporter with different options.

Preview replacement is staged while the existing rendered document remains visible. DOCX renders in a connected invisible host; HWPX decodes its first visible pages before committing and reserves dimensions for later lazy pages. The new content replaces the old content in one DOM operation, then old object URLs are revoked. Cancellation removes staged hosts/URLs and prevents late commits. Changes that leave an individual preview request unchanged only update inclusion/save availability. A checkbox never changes the preview target; file names do. Refreshes of the same document retain preview scroll offsets.

Font/paragraph distances are pt; paper/margins are mm. DOCX uses twips (20/pt, 1440/inch); HWPX uses HWPUNIT (100/pt, 7200/inch). Spacing is percentage or fixed/at-least/between-lines. Word uses an equivalent exact line distance for between-lines.

## Template adapter and precedence

`HwpxTemplate` rejects invalid ZIPs, invalid paths, excessive expanded sizes, DTD/entities, missing styles and missing page settings. It reads the first section (manifest spine where available), identifies body char/paragraph combinations by frequency, and keeps their native XML. Tables, headers, footers and notes do not determine the representative body style. It reads a solid page border fill; unsupported image/gradient backgrounds produce a warning.

The writer copies the template reference definitions together, preserving existing IDs; new fonts/char/paragraph/fill definitions receive IDs beyond that range. It changes the chosen base style with popup overrides. It builds a new body and keeps no template body/logo/header/footer content. It imports the page geometry separately. The original template is never opened for writing.

Precedence: independent plugin defaults, selected preset/template, explicit popup edits. `documentExportDefaultPreset` selects the initial preset; a saved template path alone cannot activate it. Paths remain when selecting another preset. Corrupt/unsupported explicitly selected templates block export; errors never fall back to plain output.

`ExportDefaults` version 2 replaces the former editor-derived baseline once: all extraction toggles off, interface font, 14pt/500, theme text/background colors, justified text, 10pt indent, 200% spacing, zero paragraph margins, A4 with 20mm top/bottom and 10mm side margins. Named presets and external paths survive this migration. Appearance flags allow factory font/colors to resolve against the current document's interface/theme when opening; explicit popup defaults saves detach changed values. Color reset resolves the current theme as well.

The export settings page contains only a Defaults group with directory, template, hierarchy, overwrite, initial preset, initial format and seven content toggles, followed by a Manage presets navigation item. Preset/format selectors use native `Setting.addDropdown`; removed style controls are no longer included in settings-search metadata. Named-preset content toggles edit that preset, while default/template selections edit the baseline. The preset management page reuses the proper-noun list structure: native heading with +, inline name entry, `.mod-list.mod-no-icon` group, `.setting-list-item` rows and remove buttons. Adding snapshots the selected preset/baseline; removing the initial preset resets its selector to default. Actual style editing stays in the export popup.

## UI, security and extension points

`DocumentExportModal` owns session state. Its manuscript state is named `sourceSelection`: Obsidian's `Modal.open()` writes the unrelated native text-selection snapshot to `selection`. Subclasses must not use that property for export state. `ExportSelection` owns order/tri-state selection without moving files. `ExportControls` is shared by the popup and default settings. All entrypoints delegate to this modal.

Export metadata rows lead directly into the native Bases toolbar, without a divider or a separate toolbar heading. `ExportSources` registers two public Bases view types, File tree and Merge; their internal type IDs remain unchanged. Like the music library, it embeds a real `.base` file using `MarkdownRenderer`. Each modal creates a unique `Writing Menu Export <session>.base` in the Vault root, which holds only query configuration and selection paths. Closing or changing project unloads the embed and deletes that same owned file through the Vault API; a renamed/replaced file is not deleted. A crash can leave a session file behind. Manuscript frontmatter is never changed.

Bases owns the normal controller, toolbar, menus, search, property selection, filters, sorting and grouping. The custom result views render inclusion checkboxes, configured property columns and preview links. Selecting Merge in the native view menu enables merged export and shows selected documents; File tree enables individual export. Merge rows show move arrows without ordinal numbers. A managed boolean formula supplies the native Merge filter, so native search and result counts operate on the selected dataset. Selection changes update that formula through `vault.process`, retaining user filters and view options. Query sorting can reorder visible selected documents without dropping filtered-out selections. Manual reordering clears the Merge view's native sort through the same file so the menu reflects manual order. Folder groups use `groupedData` and property columns use `getOrder`/`getDisplayName`/`getValue`. The adapter independently checks Markdown eligibility and project scope. No custom toolbar buttons, separate search bar or fallback collection UI is created. The component remains loaded while format settings/output format change, preserving its native query state.

`ExportBasesPortal` marks only native menus, backdrops and nested suggestions opened from that export's Bases host or its owned menus. They retain their original body mount, positioning, focus, event handlers and keyboard scopes. Scoped CSS raises these marked nodes above the modal; no popup is reparented. In particular, moving a focused native combobox would trigger its focusout close handler and break nested property/operator/direction/layout choices. Native close handlers run before sidebar changes and disposal. Global menu layers are unchanged. The native New toolbar item is hidden because this is a document selection view. The result table has no cell borders; the header checkbox uses the original theme sizing, the metadata icon/title gap and a 13px bold project name. All leading metadata/view icons share the native Bases icon size/stroke variables and explicit center alignment with 20px title line boxes. Indentation guides terminate outside the theme's checkbox bounds. Folder titles toggle folding directly, with a muted collapsed state and an inline parenthesized descendant count.

Initial reveal expands the active note's ancestors, then uses animation-frame scheduling and a ResizeObserver to wait for a measurable list before scrolling to the note. The one-time reveal flag is retained while the list is hidden or unmeasured. The scroller itself remains mounted across result updates: a replacement table is built off-DOM and installed atomically. Logical scroll offsets are restored after layout, not read from a transiently empty, detached or clamped viewport. Pending restoration and the last applied offsets prevent synthetic scroll events from overwriting the saved position with zero. Native scroll anchoring is disabled for this managed scroller. Sidebar remounts reuse the same element and saved position.

DOM/CSS uses native Obsidian controls and variables; no React/Tailwind runtime is added. The format drill-down page and named presets remain independent of source selection. The main project, directory and format actions use left-hand icon buttons; project menus anchor to that icon. It reuses ToolbarSelect, toolbar font/color controls and the shared wm-segmented-control base. Value fields reference the visible row label using `aria-labelledby` instead of tooltip-producing `aria-label`/`title` attributes. Zoom controls sit beside the top-right close icon with 14px gaps. The toolbar, preview and footer all belong to the right column, leaving the left collection full height. The preview frame has equal external top/bottom margins; only its inner viewport scrolls, so the bottom gap remains visible at every scroll position. Fit zoom uses the viewport's actual content width without subtracting those external margins again. Status and errors appear at the left end of the right-column footer opposite Export. The footer has no cancel button or permanent document-count/format summary, and no persistent preview explanation is rendered. The width separator, document selection and merge order support keyboard input; a compact settings/preview switch handles narrow windows. Ctrl/Cmd-wheel zoom is local to the preview.

The format page has Basic, Content selection, Text, Paragraph and Paper sections, with 13px black/white headings in light/dark themes. Preset save and template load use the leading row icon, and the back row follows the same metadata geometry. Template representative style selection is automatic and updates the ordinary font/paragraph/paper inputs. Every content selection uses a native toggle, including the separate project-formatting toggle. Color and paper background use Obsidian ColorComponent with a native reset button, native control spacing and enough swatch padding for the hover ring. Alignment icons align flush with the right edge and use a heavier stroke for the selected alignment. `toolbar/FormatSlider` is shared by the editor and export controls, including its native range, filled track and min/current/max labels; export slider blocks have a 6px bottom margin and their sections have 8px vertical padding. Font size and weight use sliders; weight stores 100–900 in steps of 100 and displays the editor's localized descriptions instead of numbers. Indentation uses a slider from zero without a separate numeric input; line spacing combines full-width mode segments matching the margin selector and one slider with per-mode session values. Paragraph/paper margins use direction segments and one slider for the selected direction. Dropdowns have 30px bordered frames that fit the selected label using intrinsic max-content sizing. Both wrapper and trigger disable flex growth and cap their width at the value column; hidden native selects do not affect sizing. They remain right aligned with fixed padding/gaps and 13px chevrons, truncating only when the selected label exceeds the available row width. Paper width/height remain borderless numeric fields with mm aligned to the far right. Hover does not add a gray background, while selection and CTA backgrounds remain. The paper orientation row and legacy one-space indentation control are absent. The sidebar becomes inert during saving so native toggles cannot alter an in-flight export. The tree/merge project header is an opaque isolated sticky table head above descendant checkboxes; other column headings are centered. View-menu icons/titles inherit the toolbar button color so both icons and the label highlight together on hover, as do the right-hand toolbar controls. Tree connector segments are unioned into a single mask per row, using pixel-aligned 1px lines; translucent guide colors are painted once even at intersections.

Only external template reads and external output writes use fs. Temporary Bases configuration uses the Vault API. Generated paths are preflighted for collisions and template overwrites. Preserve-folder-structure and overwrite-existing-output are plugin settings, defaulting to false and true respectively; the export toolbar has no storage options. The default writes directly into the selected output folder. Success notifications include the actual first output file path, including subdirectories when hierarchy is enabled. The template original is protected regardless of overwrite preference. Partial failures report how many files were written. `DesktopExport` only launches fixed Windows/macOS picker scripts with literal argument arrays and `shell:false`. AI CLI integration is unchanged. See the exact capability inventory in `scripts/warning-exceptions.json`.

## Verification

- `node scripts/verify-document-codecs.mjs`: independent XML/text extraction, Unicode/whitespace/tabs, element policy, resources, template styles and long manuscripts.
- `node scripts/verify-export-boundaries.mjs`: Vault boundary, live editor flush, cache bytes, ordering/hierarchy/merge, template hash/errors, collision/permission errors, settings migration and inert picker contracts.
- `node scripts/verify-export-ui.mjs`: headless Chromium with the real Worker, DOCX/SVG rendering, selection/search/order, keyboard resize, cancellation/save/error/default state, themes and small window. Obsidian host APIs are contract doubles, not a substitute for plugin installation testing.
- `node scripts/verify-hwpx-native.mjs`: opt-in Windows integration using only synthetic files and new automation objects. This **test** uses COM to open/resave files; production export does not. Hancom's TEXT automation API omits soft breaks; native roundtrip XML is the authoritative check for those breaks and trailing empty paragraphs.

Native macOS Word/Hangul opening and the macOS dialog require verification on a Mac. No claim of macOS native verification is made by Windows contract/browser tests. The full release check runner keeps production builds and deployment separate.
