# 문서 내보내기

Windows·macOS에서 TXT·DOCX·HWPX를 만듭니다. Python, Word, 한글 설치가 필요하지 않습니다. 툴바, 파일·폴더 우클릭, 다중 선택, Notebook Navigator 또는 **문서 내보내기** 명령으로 같은 팝업을 엽니다.

## 문서 선택과 저장

툴바 내보내기 아이콘을 누르면 현재 문서가 체크된 팝업을 바로 열고, 파일 트리에서 해당 노트 위치로 스크롤합니다. 목록의 실제 높이가 잡힌 뒤 위치를 계산하며 상위 폴더도 펼칩니다. 왼쪽은 **포맷 → 프로젝트 → 파일 이름 → 저장 경로 → 양식 → 기본 Bases 툴바 → 문서 목록** 순서로 이어집니다. 양식과 Bases 툴바 사이에 여백·구분선을 두지 않으며, 보기 이름의 아이콘 위치와 제목 간격도 위 항목과 맞춥니다. 프로젝트를 바꾸지 않으면 진입 당시 문서 선택과 순서를 유지합니다.

1. 맨 위 중앙의 TXT·DOCX·HWPX 선택기로 포맷을 고릅니다. 프로젝트 왼쪽 아이콘을 누르면 해당 위치에 프로젝트 선택 목록이 열립니다.
2. 기본 Bases 툴바의 검색·필터·정렬·그룹·속성을 사용해 문서를 찾고 표시할 열을 고릅니다. 추가(+) 버튼은 표시하지 않습니다. **파일 트리** 보기에서는 문서를 체크하며 이름을 누르면 미리보기 대상만 바꿉니다. 맨 위 전체 선택 체크박스 옆에는 선택한 프로젝트명을 13px 굵은 글씨로 표시합니다. 체크박스는 원래 Obsidian 테마 규격을 따릅니다. 항목의 왼쪽 아이콘은 Bases 툴바와 같은 크기·선 굵기를 사용하며, 제목과 세로 중심·간격을 맞춥니다. 목록은 구분선 없이 전체 선택 체크박스 아래로 아웃라인이 이어지고, 하위 폴더·문서마다 한 단계씩 들여씁니다. 연결선은 빈 체크박스 안으로 들어가지 않습니다. 폴더 제목을 눌러 접거나 펼치고, 접힌 제목은 흐리게 표시합니다. 폴더 제목 옆 괄호에는 현재 조회된 하위 문서 수를 표시하고 폴더 체크박스는 전체·부분 선택을 표시합니다. 검색·필터로 숨겨진 문서의 선택은 유지됩니다. Bases 조회 결과나 사이드바가 갱신되어도 기존 스크롤 영역과 위치를 유지합니다.
3. 파일 이름과 저장 경로를 지정합니다. 저장 경로 왼쪽 아이콘으로 외부 폴더를 선택합니다. 개별 모드는 각 문서 이름, 병합 모드는 입력한 이름으로 저장합니다. 저장 경로가 비어 있으면 저장할 때 선택하고, 선택 취소 시 저장하지 않습니다.
4. 기본 보기 메뉴에서 **병합** 보기를 선택하면 체크한 문서들을 하나의 파일로 내보냅니다. 이 보기에서 위·아래 버튼, Alt+방향키 또는 드래그로 병합 순서를 바꿉니다. 화살표 옆 순번 숫자는 표시하지 않습니다. 정렬 메뉴로 지정한 순서는 병합 순서에 적용하고, 직접 이동하면 수동 순서로 전환합니다. **파일 트리** 보기로 돌아오면 개별 내보내기가 됩니다. 별도의 병합·저장 옵션 버튼은 없습니다.
5. 저장 경로 아래 **양식 왼쪽 아이콘**을 누르면 왼쪽 전체가 양식 페이지로 바뀝니다. 뒤로가기로 내보내기 항목에 돌아옵니다. 문서 선택, 검색과 Bases 조회 설정은 유지됩니다.

파일트리 연결선의 꺾이는 모서리는 둥글게 표시합니다. 선에 포인터를 올리면 그 폴더에 속한 연결선만 강조하며, 선을 누르면 해당 폴더가 접힙니다. 폴더 제목으로 다시 펼칠 수 있습니다. 프로젝트에서 내려오는 선은 프로젝트 전체를 접으며, 고정된 프로젝트 제목을 누르면 다시 펼칩니다. 연결선으로 폴더를 접어도 문서 선택과 미리보기 대상은 바뀌지 않습니다.

문서 조회는 [Bases 사용자 정의 보기 API](https://docs.obsidian.md/plugins/guides/bases-view)와 [기본 Base 파일 임베드](https://obsidian.md/help/bases/create-base)를 사용합니다. 음악 라이브러리와 같은 방식으로 기본 컨트롤러·툴바·메뉴를 사용하며, Vault 루트에 `Writing Menu Export <세션 ID>.base`를 임시로 만듭니다. 이 파일에는 조회·표시 설정과 선택 경로를 보관하고 창을 닫거나 프로젝트를 바꾸면 정리합니다. 원고와 frontmatter는 수정하지 않습니다. Obsidian이 비정상 종료되면 임시 파일이 남을 수 있습니다. 목록을 사용하려면 Bases 코어 플러그인이 켜져 있어야 합니다.

**설정 → 편집기 → 내보내기 → 기본값**에서 **폴더 구조 유지**, **파일 덮어쓰기**를 선택합니다. 최초 기본값은 폴더 구조 유지 **꺼짐**, 파일 덮어쓰기 **켜짐**입니다. 기본 상태에서는 선택한 저장 폴더 바로 아래에 파일을 만듭니다. 폴더 구조 유지를 켜면 개별 내보내기에서 프로젝트 기준의 하위 폴더를 만듭니다. 완료 알림에는 첫 번째 파일의 실제 저장 경로를 표시합니다. 템플릿 원본 덮어쓰기는 설정과 관계없이 차단됩니다.

오른쪽에는 생성 결과가 표시됩니다. 최상단 우측에 축소·배율 초기화·확대·닫기(X)를 14px 간격으로 배치합니다. 미리보기 위에서 Ctrl/Cmd+휠로 배율을 조절합니다. 기본 창 너비는 1120px이며 화면 너비에 맞춰 줄어듭니다. 미리보기 위·아래 여백은 스크롤 영역 바깥에 두어 스크롤 위치와 관계없이 동일하게 유지합니다. 오른쪽 하단 줄의 왼쪽에 생성 중 상태·오류, 오른쪽에 내보내기 버튼을 표시합니다. 왼쪽 목록은 창 바닥까지 사용합니다. 취소 버튼·문서 수/포맷 요약·상시 서식 안내는 표시하지 않습니다. 항목 내용과 대화상자·문서 목록·너비 조절선·미리보기 영역에는 툴팁을 붙이지 않고 접근성 이름을 별도 레이블로 연결합니다. 좁은 창은 설정·미리보기 버튼으로 전환합니다.

## 양식과 프리셋

양식 페이지 맨 위의 **돌아가기** 아이콘으로 문서 선택 화면에 돌아갑니다. 페이지는 **기본 → 추출 범위 → 글자 → 문단 → 용지**의 다섯 섹션을 한 열로 표시합니다. 섹션 제목은 13px이며 밝은 테마에서는 검정, 어두운 테마에서는 흰색입니다. 기본 섹션에서 프리셋을 선택합니다. 템플릿 항목은 HWPX 포맷에서 템플릿 프리셋을 고른 경우에만 나타납니다. 다른 프리셋에서는 항목 전체를 숨기며 비활성 아이콘이나 안내 문구를 남기지 않습니다. 기존 템플릿 경로는 보존합니다.

**프리셋 제목 왼쪽 아이콘**을 눌러 이름을 지정해 사용자 프리셋으로 저장합니다. 기본 서식은 덮어쓸 수 없습니다. **템플릿 제목 왼쪽 아이콘**으로 외부 HWPX 파일을 불러옵니다. 같은 이름의 사용자 프리셋은 갱신합니다. 저장된 사용자 프리셋은 내용·글자·문단·용지 설정을 보관합니다. 팝업에서 수정한 값은 명시적으로 저장하기 전까지 이번 작업에만 적용합니다. 글꼴은 폭을 줄인 에디터 툴바 선택 컨트롤을 사용합니다. 글자 크기와 두께는 제목 아래의 슬라이더로 조절합니다. 두께는 내부적으로 100~900을 100 단위로 저장하며, 화면에는 ‘가장 가늘게 → 아주 가늘게 → 가늘게 → 보통 → 중간 → 조금 두껍게 → 두껍게 → 아주 두껍게 → 가장 두껍게’를 표시합니다. 글자색·용지 배경색은 Obsidian 기본 색상 선택기와 초기화 버튼을 사용합니다.

DOCX·HWPX의 세부 두께는 설치된 글꼴의 해당 굵기 서체로 연결합니다. 선택한 두께가 없으면 사용 가능한 가장 가까운 두께를 사용합니다. 글꼴 정보를 읽지 못하거나 해당 글꼴이 설치되지 않았으면 일반·굵게로 대체하며, 이런 경우에는 하단 상태 줄에 ‘글꼴에 따라 지원하는 두께값에 차이가 있을 수 있습니다’를 표시합니다. 출력 파일에 글꼴 파일 자체를 포함하지 않으므로 다른 컴퓨터에서는 설치된 글꼴에 따라 표시가 달라질 수 있습니다.

문단 정렬은 오른쪽 끝에 붙인 아이콘으로 선택하며 현재 정렬 아이콘의 선을 굵게 표시합니다. 들여쓰기는 별도 숫자 입력칸 없이 0pt부터 시작하는 슬라이더로 조절합니다. 줄간격은 여백과 같은 폭의 비율·고정·최소·간격 분할 선택기에서 방식을 고르고 바로 아래 슬라이더로 조정합니다. 방식을 전환하면 해당 작업에서 마지막으로 조절한 값을 다시 표시합니다. 문단·용지의 ‘여백’에서는 위·아래·왼쪽·오른쪽 선택기를 누른 뒤 아래 슬라이더로 선택한 방향의 값만 조절합니다. 슬라이더는 에디터 툴바의 서식 컨트롤과 같은 구현을 사용하며 블록 아래 margin은 6px, 내부 섹션 padding은 8px 0입니다.

줄간격의 비율은 글자 높이에 대한 백분율, 고정은 줄 전체 높이를 지정한 pt로 고정하는 방식, 최소는 지정한 pt 이상을 확보하되 내용에 따라 늘어나는 방식입니다. 간격은 글자 높이에 추가할 줄 사이 여백을 지정합니다. 단위가 같아도 계산 기준이 다릅니다. [한컴 줄간격 도움말](https://help.hancom.com/hoffice130/ko-KR/Hwp/format/paragraph/paragraph%28line_spacing%29.htm)

용지는 규격·너비·높이·여백·배경색 순서이며 방향은 너비·높이로 정합니다. 양식 선택창은 선택한 내용 길이에 따라 폭이 바뀌며 오른쪽 끝에 정렬합니다. 높이·테두리·화살표와 안쪽 여백은 일정하게 유지합니다. 긴 이름은 해당 행의 내용 영역 안에서만 늘어나고 초과 부분은 말줄임으로 표시합니다. 용지 너비·높이 입력칸에는 테두리를 두지 않고 mm를 오른쪽 끝에 정렬합니다. 팝업의 회색 호버 배경은 사용하지 않으며 선택 상태의 배경은 유지합니다. Bases 보기 버튼의 양쪽 아이콘과 제목은 호버 시 함께 강조하며 우측 툴바 아이콘에도 호버 색을 적용합니다.

병합은 선택 순서를 따르고 원고 사이에 줄바꿈 두 개를 추가합니다. 원고 자체의 앞뒤 빈 줄도 남습니다. 일부 저장 뒤 실패하면 저장된 개수와 오류를 표시합니다.

## 내용과 서식

| 요소 | 선택 | 처음 기본값 |
| --- | --- | --- |
| 속성 | 켜기 / 끄기 | 끄기 |
| 헤딩 | 켜기 / 끄기 | 끄기 |
| 표 | 켜기 / 끄기 | 끄기 |
| 각주 | 켜기 / 끄기 | 끄기 |
| 강조 | 켜기 / 끄기 | 끄기 |
| 이미지 | 켜기 / 끄기 | 끄기 |
| 서식 | 켜기 / 끄기 | 끄기 |

추출 범위는 모두 토글로 켜고 끕니다. 속성을 포함하면 원본 YAML의 내용만 평문으로 넣으며 구분자 `---`는 넣지 않습니다. 병합 시에도 각 원고 앞에 해당 속성을 유지합니다. 헤딩은 제목 텍스트, 표는 탭으로 구분한 행, 각주는 번호·본문을 평문으로 가져옵니다. **서식**을 켜면 DOCX·HWPX의 헤딩과 각주에 플러그인의 Style Settings에서 지정한 글꼴·크기·두께·색·줄간격을 적용하며, 각주는 실제 각주로 만듭니다. 표는 서식 토글과 관계없이 텍스트로 가져옵니다. TXT에서는 서식 토글을 비활성화합니다.

본문의 앞뒤 빈 줄·연속 빈 문단·탭·한글·영문·이모지·XML 특수문자와 문단 안 줄바꿈을 보존합니다. 문단 앞에 공백 한 칸을 추가하는 옵션은 제거했으며 들여쓰기는 문단의 수치 설정을 사용합니다. Markdown 문법 기호는 해당 요소로 해석하며 자동 문장 교정은 하지 않습니다. 목록·인용은 현재 원문의 줄 구조와 기호를 텍스트로 보존합니다.

강조를 켜면 Markdown 강조와 Paged 뷰에 저장된 굵게·기울임·밑줄·취소선·글자색·배경색을 변환합니다. 문서 전체 글꼴·문단 정렬·간격·쪽 설정은 팝업 값이 우선합니다. 원문 위치와 개별 문단 정렬 정보는 공통 모델에 보관합니다.

이미지를 켜면 Vault 안의 PNG·JPEG·GIF·BMP·WebP·SVG 파일을 삽입합니다. Markdown 이미지와 Obsidian `![[이미지]]`를 해석합니다. 확장자와 실제 형식이 다르면 파일 내용으로 형식을 판별하며 원본 파일 이름은 바꾸지 않습니다. PNG·JPEG는 원본 데이터를 사용하고, 나머지는 브라우저에서 PNG로 변환합니다. GIF는 정지 화면을 사용합니다. 본문 너비 또는 높이보다 크면 비율을 유지해 줄입니다. 외부 URL 이미지는 다운로드하지 않습니다. 지원하지 않는 파일·손상된 그림은 해당 경로를 포함한 오류를 표시하며, 이미지를 끄면 해당 그림을 제외합니다. TXT는 이미지가 켜져 있을 때 대체 텍스트만 남깁니다.

TXT는 UTF-8이며 글꼴·쪽 설정을 저장하지 않습니다. 해당 컨트롤은 비활성화하고 최종 평문을 보여줍니다. DOCX·HWPX는 생성된 파일을 미리 봅니다. Word·한글의 글꼴 대체와 자동 쪽 나눔에 따라 실제 프로그램의 배치가 달라질 수 있습니다.

문서 선택과 체크는 분리됩니다. 체크는 내보내기 포함 여부만 바꾸고, 이름을 눌러 미리 볼 문서를 바꿉니다. 새 미리보기가 준비될 때까지 현재 화면을 유지하며, HWPX는 처음 표시할 쪽의 그림 디코딩 후 교체합니다. 같은 문서를 갱신할 때는 미리보기 스크롤 위치를 유지합니다.

파일 트리·양식 페이지의 스크롤바는 Obsidian의 기본 스크롤바 설정을 따릅니다. Hider에서 스크롤바 숨김을 켜면 이 영역에도 적용됩니다.

## HWPX 템플릿

**양식 → 프리셋: 템플릿 → 템플릿 불러오기**로 외부 `.hwpx`를 선택합니다. Windows와 macOS에서 똑같이 파일을 해석하며 한글 오토메이션을 실행하지 않습니다. `.hwp`는 한글에서 HWPX로 저장해 사용합니다.

첫 구역의 쪽 설정과 가장 많이 사용하는 일반 본문 서식을 자동으로 적용하며 글꼴·크기·문단·용지 항목의 수치를 갱신합니다. 별도의 ‘기준 서식’ 선택 항목은 없습니다. 적용된 글꼴·크기·줄간격·문단 간격·들여쓰기·정렬·용지·여백·단색 배경을 수정할 수 있습니다. 그림·그라데이션 배경은 지원하지 않습니다.

템플릿 본문·로고·고정 표·머리말·꼬리말은 복제하지 않습니다. 필요한 서식 정의와 참조를 새 문서로 복사하고 새 정의의 ID를 충돌하지 않게 할당합니다. 템플릿 원본은 읽기만 합니다. 읽기·적용이 실패한 상태에서는 일반 문서로 자동 대체하지 않습니다.

적용 순서는 **내보내기 기본값 → 선택한 프리셋·템플릿 서식 → 팝업 수정값**입니다. 시작 프리셋이 템플릿일 때만 저장된 템플릿을 적용하며, 경로가 저장되어 있다는 이유로 자동 활성화하지 않습니다. 다른 프리셋으로 바꿔도 템플릿 경로는 남습니다.

## 기본값과 기존 설정

설정 → 편집기 → 내보내기의 **기본값**에는 다음 순서로 항목을 표시합니다.

1. 저장 경로
2. 템플릿
3. 폴더 구조 유지
4. 파일 덮어쓰기
5. 프리셋
6. 포맷
7. 속성
8. 헤딩
9. 표
10. 각주
11. 이미지
12. 강조
13. 서식

프리셋·포맷은 Obsidian 순정 선택창을 사용하며 내보내기 팝업을 열 때의 초기 선택을 정합니다. 사용자 프리셋을 선택하면 아래 추출 항목에도 해당 프리셋의 값을 표시하며 변경값을 그 프리셋에 저장합니다. 기본값·템플릿을 선택한 경우에는 공통 추출 기본값을 설정합니다. 설정 페이지에는 글자·문단·용지 편집 컨트롤을 표시하지 않습니다.

최초 기본 서식은 다음과 같습니다. 예전 편집기 값에서 복사한 내보내기 기본값도 이 서식으로 한 번 이관하며, 저장 경로·템플릿 경로·사용자 프리셋은 보존합니다.

| 구분 | 기본값 |
| --- | --- |
| 추출 범위 | 모든 항목 꺼짐 |
| 글꼴 | Obsidian 인터페이스 글꼴 |
| 글자 | 14pt, 중간(500) |
| 글자색·바탕색 | 현재 Obsidian 테마의 기본 글자색·배경색 |
| 정렬·들여쓰기 | 양쪽 정렬, 10pt |
| 줄간격 | 비율 200% |
| 문단 여백 | 위·아래·왼쪽·오른쪽 0pt |
| 용지 | A4(210×297mm) |
| 용지 여백 | 위·아래 20mm, 왼쪽·오른쪽 10mm |

기본 서식은 위 값으로 고정하며 글꼴·색은 창을 열 때 현재 테마를 따릅니다. 이전 버전에서 기본값으로 저장했던 글자·문단·용지 변경값도 기본 서식을 덮어쓰지 않습니다. 팝업의 변경값은 사용자 프리셋으로 저장할 수 있습니다. 시작 포맷과 추출 범위는 플러그인 설정에서 관리합니다.

내보내기 설정 페이지에 **프리셋** 목록을 바로 표시합니다. 별도의 관리 페이지 없이 고유명사 관리와 같은 목록 디자인을 사용합니다. 제목 오른쪽의 `+`를 눌러 이름을 입력하고 Enter로 추가합니다. 새 프리셋은 현재 선택된 사용자 프리셋 또는 기본값을 복사합니다. 세부 서식은 내보내기 팝업에서 바꾸고 같은 이름으로 저장하면 갱신합니다. 각 항목 오른쪽의 `×`로 삭제하며, 시작 프리셋을 삭제하면 시작 선택은 기본값으로 돌아갑니다.

팝업의 수정은 이번 작업에만 적용하며 프리셋 저장 창에는 사용자 프리셋 저장 기능만 있습니다. 템플릿·저장 경로의 시작값은 플러그인 설정에서 지정합니다. 예전 프리셋을 불러와도 제거된 한 칸 공백 옵션은 적용하지 않습니다. Python 스크립트나 한글 COM은 사용하지 않습니다. 이전 버전이 남긴 스크립트를 자동 삭제하지는 않습니다.
